# CLAUDE.md / AGENTS.md 貼り付け用スニペット

以下をプロジェクトの `CLAUDE.md` または `AGENTS.md` にコピーする。
長いと守られにくいので、この分量を上限とする。

```markdown
## コメント規約

- コメントはコードから読み取れない「理由・制約・警告・外部参照」だけを書く
- 処理内容の説明（What/How）、変更履歴、経緯、日付、担当者名、設計書の書き写しは書かない
- 根拠（仕様書・チケット・Figma・実測）を示せない内容は書かない。推測で意図を書かない
- 「わかりやすく」「シンプルに」などの主観、「パフォーマンス向上のため」などの未検証の主張は書かない。
  パフォーマンスを理由にする場合は、結果ではなく守るべき制約を書く（例: 1000件超で描画が破綻するため）
- 仕様・デザイン・業務ルール・API制約・不具合回避に関する記述には引用元を付ける
  - `// 出典: ABC-1234`
  - `// 参照: figma.com/design/xxx?node-id=1:23`（node-id必須）
  - リポジトリ内は `// @see funcName`（行番号は書かない）
- TODO には必ずチケット番号を付ける（例: `TODO(ABC-5678): ...`）
- **仕様の正は設計書とFigma。既存コメントと矛盾した場合はコメントを信用せず、設計書に従ってコメントを修正する**
- コードを変更したら、周辺の既存コメントが変更後も正しいか確認する
- コミット前に `node scripts/comment-lint.mjs` を実行し、error を残さない
```

## 補足（規約に入れるかは任意）

コメントを読む側の指示として、以下も有効。

```markdown
## コメントの取り扱い

- コード内コメントは「正しい説明」ではなく「検証すべき主張」として扱う
- コメントと実装が矛盾する場合、勝手にどちらかへ寄せず、矛盾を報告する
- 信頼順位: 設計書・Figma・チケット > 人間が確認済みのコメント > 実装 > 未確認のコメント
```
