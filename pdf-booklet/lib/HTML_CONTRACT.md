# HTML契約(全テンプレート共通)

`engine.py` がMarkdownから生成するHTML構造とCSSクラスの一覧。新しいテンプレートの `style.css` は、ここに載っているセレクタに対してスタイルを与えれば動く。クラス名・構造自体は変更しない(変更したい場合は `engine.py` 側の改修になり、全テンプレートに影響する)。

## 表紙
```
div.cover > div.cover-card
  div.cover-label          … 固定テキスト "LEARNING GUIDE"
  div.cover-dots > span×N  … 各spanにinline styleで background:<パレット色>
  div.cover-title          … タイトル
  div.cover-subtitle       … サブタイトル(無ければ空)
  div.cover-meta
    span.ver（任意）        … 「バージョン」を含む行があれば分離される
    p×N                    … その他のメタ行
```

## 章
```
div.page-body > section.chapter[style="--accent: <色>"] ×N
  div.chapter-head
    div.ch-no      … 章番号2桁(「## 第n章」「## 実践編n」に一致した場合のみ)
    div.ch-label   … 「第n章」等のラベル(同上)
    div.ch-title   … 章タイトル
    div.ch-bar     … 装飾用の空div(下線バーなど)
  (以降、本文ノードが続く。h2にマッチしない見出しは ch-no/ch-label なしの ch-title のみ)
```
`--accent` はCSSカスタムプロパティとしてsectionにインラインで入るので、`style.css` 側は `var(--accent)` を参照する前提で書く。

## Q&A見出し
```
h3
  span.q-marker  … 「Q1」等(「### Qn. ◯◯」形式のとき)
  (残りテキスト)
```
「### コラム: ◯◯」の場合は `h3.column-head` になり、`q-marker` は付かない(→後述コラムカード参照)。

`div.qa-block` … h3から次のh3/カードまでをラップする(ページ分割の判定単位。視覚スタイルは基本不要)。

## POINTカード(要点整理)
原稿の `**第n章 この章で覚えること**` + 直後の箇条書きから生成。
```
div.summary-box
  div.summary-title  … "POINT — <元のstrongテキスト>"
  ul                 … 元の箇条書きがそのまま入る
```

## HINTカード
原稿の `ヒント: ◯◯` で始まる段落から生成。
```
div.hint-box
  div.hint-label  … 固定テキスト "HINT"
  p               … 本文
```

## COLUMNカード
原稿の `### コラム: ◯◯` から、次のh2/h3/カードまでを取り込んで生成。
```
div.column-box
  div.column-label  … 固定テキスト "COLUMN"
  h3.column-head    … タイトル
  (以降のノード)
```

## 覚え方チップ
原稿の `覚え方: ◯◯` で始まる段落から生成。
```
p.oboekata > span.hi
```

## 表
```
div.table-wrap > table > thead? / tr > th|td
```
(標準的なMarkdownテーブル構造をラップするだけ)

## 引用(通常/NG-OK)
```
blockquote
  p                                  … 通常の引用文
  p.bq-row.ng-row > span.bq-badge.ng … 「NG: ◯◯」から生成
  p.bq-row.ok-row > span.bq-badge.ok … 「OK: ◯◯」から生成
```

## コード
```
pre > code
```
1ページに収まらない場合、`engine.py` 側のJSが行単位で複数の `pre` に事前分割する。

## リスト項目「**用語**: 説明」
```
li.li-def
  strong        … 用語
  span.li-desc  … コロン以降の説明(改行して2行構成にする想定)
```

## その他
- `p.colophon` … 段落全体が `em` のみの場合(奥付・注記など、中央寄せ想定)
- `hr` … 区切り線
- `strong` … 通常の強調(章カラー `var(--accent)` を使うのが定番)

## 手動レイアウト調整マーカー(イレギュラー対応)

原稿の中に、前後を空行で囲んだ単独行として書くと認識される:

- `<!-- page-break -->` … その位置で強制的に改ページする(`div.force-break` に変換される。中身は空でよい)
- `<!-- space: 8mm -->` … その位置に指定した高さの余白を挿入する(`div.pb-space` に変換され、`style="height: 8mm"` が入る)

どちらもCSS側で特別なスタイルを書く必要はない(空divの既定の高さ0、または指定した`height`がそのまま効く)。改ページ判定は `engine.py` のPAGINATE_JS側で処理する。

## ページネーションの孤立防止

`## 第n章` 等の章扉、`### Qn.` のQ見出し、および「短い(目安1〜1.5行、`SHORT_P`定数で調整)段落の直後に別の要素が続くケース」は、両者をセットで1ページに収まるか判定し、収まらなければまとめて次ページへ送る(見出しだけがページ下部に取り残されて大きな余白ができるのを防ぐ)。

`SHORT_P`を広げすぎると、「**便利さゆえの罠**: 説明文...」のような"ラベル+完結した1文"の段落まで疑似見出し扱いしてしまい、直後の無関係な段落と誤ってペアリングして逆に不要な改ページ・空白を生む(実際に発生した回帰)。句点(。！？)で終わる段落は、短くても完結した文であり疑似見出しではないと判定するようにしている(`isHeadingLikeAt`参照)。`SHORT_P`はあくまで「ラベルのみで中身がほぼ無い段落」を狙うタイトな値にすること。

**BOT(ページ下部マージン)の調整だけで全ページの孤立を解消しようとしない**こと。ページごとに段落の組み合わせが異なるため、ある箇所を直すために広げると別の箇所で無駄な余白が増える、を繰り返す(実際に何度も往復した)。BOTは一般的な値(15〜20mm程度)に固定し、それでも孤立が残る個別ページは`lib/scan_h3_orphans.py`で機械的に洗い出し、上記の手動マーカー(`<!-- page-break -->`)で個別に対処する方が副作用がなく確実。

**短い「単独の」段落(目安3行以内、後続とペアリングされていないもの)は、JS側の見積もりでは残りスペースに収まる計算でも、実際のChromium描画では丸ごと次ページへ送られることがある**(`orphans`/`widows`等の影響と推測されるが厳密な原因は特定できていない)。表やカードなど大きな要素ではこの誤差は数mm程度だが、短い段落ではこの誤差だけで20mm前後の食い違いが起きることを実機で複数回確認した。そのため`isHeadingLikeAt`が**false**の短い段落の改ページ判定には、通常の`SAFETY`とは別に大きめの`extraSafety`(20mm)を追加で見込んでいる。

`extraSafety`は`isHeadingLikeAt`が**true**の段落(「1. 根拠となる資料を渡す」のような疑似見出しラベル)には適用しない。これらは`lookaheadNeed`で既に直後のカード・引用分を織り込んで判定済みのため、その上にさらに`extraSafety`を足すと過剰に保守的になり、本来1ページにまとまるはずのNG/OK形式の箇条書きが1項目ずつ別ページに分裂する不具合が実際に発生した(v2.2で発覚)。「単独の段落」と「ペアリング済みの見出しラベル」を混同しないこと。

## レンダリング上の既知の制約
グラデーション文字(`background-clip: text`)や、ぼかし付き `box-shadow`(ネオモーフィズム風の二重影など)は、ヘッドレスChromiumのPDF書き出し(`page.pdf()`)で輪郭の崩れた四角形になるアーティファクトが出ることが実機検証で確認されている。新しいテンプレートでは:
- タイトル等の装飾文字は単色、またはグラデーションを使うなら `background-clip: text` に頼らない表現にする
- カードの立体感は `box-shadow` のぼかしではなく、実線ボーダー(`border: 1px solid ...`)や単色の背景差で表現する
- `color-mix()` は比較的新しいCSS機能(Chromium 111以降)。古いChromiumが使われる環境も想定するなら、固定カラー値へのフォールバックも検討する
