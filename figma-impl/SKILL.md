# figma-impl

Figma からの実装を、**取得 → 実装 → 検証**の3フェーズに固定する。

読み取りと生成を混ぜないことが要点。混ぜると、読めなかった箇所を生成側の推測が静かに埋め、出力を見ても「読んだ値」と「創作した値」が区別できなくなる。区別できないから、修正がランダムウォークになる。

## ハードストップ

**最初にこれを確認する。**

```bash
ls .figma-impl/conversion.md .figma-impl/defaults.md 2>/dev/null
```

**どちらか欠けていたら実装に進まない。**`figma-impl-init` を先に実行する必要があることを伝えて止まる。設定が無いまま進めると、その場の推測で埋まって元に戻る。

`FIGMA_TOKEN` が未設定の場合も同様に止まる。

## Phase 1: 取得

**AI が Figma を直接読まない。**スクリプトで機械的に取る。

```bash
# Figma で対象レイヤーを選択 → 右クリック → Copy link to selection
# で得られる URL には ?node-id= が含まれる。それをそのまま渡す
node ~/.claude/skills/figma-impl/scripts/fetch-node.js "<FigmaのURL>"

# node-id を明示的に渡すこともできる
node ~/.claude/skills/figma-impl/scripts/fetch-node.js "<FigmaのURL>" 123:456 123:789
```

**ファイル URL（`?node-id=` を含まないもの）を渡すとエラーになる。**画面全体を1回で取ろうとせず、末端のコンポーネントを1つずつ指定する運用と対になっている。

出力は `.figma-impl/tmp/nodes.json` と `nodes.md`。

**単位を小さく保つ。**画面全体ではなく、末端のコンポーネント1つずつを指定する。ツリーが深いほど、取得漏れが実装側の推測に置き換わる余地が増える。

`nodes.md` の「欠損（null）の一覧」が、**そのまま「AIが創作する場所」のリスト**になる。ここは埋まっていないのが正しい状態で、埋まっていたらスクリプトのバグ。

「混在スタイルのテキスト」の節も同じ扱いをする。1つのテキストレイヤー内で部分的にウェイトや色が違う場合、表に出ている値は**既定スタイルの代表値でしかない**。そのまま単一の値として実装すると、違いが静かに消える。要素を分割するか、該当箇所を個別に確認する。

Dev Mode MCP が使える環境なら、コード生成の足場として併用してよい。ただし**確定値は必ず `nodes.json` を正とする**。MCP の生成物には `opentypeFlags`（palt の有無）が出てこないうえ、Tailwind への丸めが入る。

## Phase 2: 実装

**`nodes.json` と `.figma-impl/conversion.md` `defaults.md` だけを見て実装する。**Figma の画面を見に戻らない。

`nodes.json` で `null` だった項目には `defaults.md` の既定値を適用し、適用したものを `UNRESOLVED.md` に記録する。

**検証で対応付けができるよう、Figma ノードに対応する DOM 要素に `data-figma-id` 属性を付ける。**これが無いと `verify.js` が突き合わせられない。

```html
<p data-figma-id="123:456" class="...">…</p>
```

### 禁止事項（実装コードに対して）

- **`letter-spacing: normal` を書かない。**値が無くても `0em` と明記する。`normal` は 0 ではなくフォント固有のカーニング
- **`line-height: normal` を書かない。**数値で指定する。`normal` の解決に使う縦メトリクスは Figma とブラウザで採用が違う
- **`font-weight` にキーワード（`bold` 等）を使わない。**数値で書く
- **トークンに存在しない生の値を書かない。**必要なら丸めずに報告する
- **表に無い値を推測で埋めない。**`defaults.md` に無ければ Phase 3 のレポートに出す

## Phase 3: 検証

**検証したいプロジェクトのルートに playwright が必要。**未導入なら先に入れる。

```bash
npm i -D playwright && npx playwright install chromium
```

```bash
node ~/.claude/skills/figma-impl/scripts/verify.js --url <実装したページのURL>
```

`getBoundingClientRect` / `Range.getClientRects` / `getComputedStyle` で実測し、`nodes.json` と突き合わせる。**出力はズレた行だけ。**

閾値は既定 ±1px。**0 にしない。**Figma はテキストをブラウザに描かせておらず（自前レンダラ、ヒンティングなし）、サブピクセル位置の丸めに原理的な差がある。0 にすると永久に緑にならない。

差分が出たら、原因の分類に従って Phase 2 に戻る。

| 症状 | 原因 |
| --- | --- |
| `letter-spacing` / `line-height` に `normal` が残っている | 変換規則の適用漏れ。**まずこれを空にする** |
| font-size は一致、幅だけ違う | tracking / palt の問題 |
| 行間だけずれて字送りは合っている | line-height のメトリクス問題 |
| font-weight 不一致・合成太字が有効 | ウェイト指定漏れ、`font-synthesis` 未設定 |

**`normal` が空になった時点で「数値は届いている」と確定できる。**そこから先に残る差異は、追う必要のない床（ラスタライザ差）だと判断してよい。

ブラウザのコンソールで手早く見るなら `scripts/check-normal.js` を貼る。

## 出力形式

### `UNRESOLVED.md`

**質問リストにしない。**Figma を作る人と実装する人は別で、事前に文章で聞いても返ってこない。ビルドを止めないことが前提。出口を3つに分けて書く。

| 分類 | 扱い |
| --- | --- |
| `defaults.md` に既定がある | 自動適用し、1行ログを残すだけ。人は見ない |
| 既定に無い（初出） | 実装者が決める。決めたら `defaults.md` に書き戻す |
| Figma にあるはずの値が欠けている | 仕様の穴ではなく `fetch-node.js` のバグ。上の2つと混ぜず、別セクションに分離する |

**項目ごとの出現回数を集計する。**「hover の指定漏れが今月17件」という数字は、Variant 化・Variable 化をデザイナーに依頼するときの材料になる（個人の要望ではなく計測結果として出せる）。

### PR 本文

`UNRESOLVED.md` の内容を**PR 本文に「Figma に指定が無かったのでこうしました」という事後報告の形で出す。**デザイナーは事前の文章には反応しないが、動くものを見ると指摘してくる。この非対称を利用する。

## 禁止事項

- **`.figma-impl/` が無い状態で実装に進まない**（ハードストップ）
- **`fetch-node.js` を通さずに Figma のスクリーンショットやコピペから値を読み取らない**
- **`nodes.json` の `null` を埋めるようスクリプトを書き換えない。**null は仕様
- **混在スタイルのテキストを、既定スタイルの値で単一に実装しない**
- **スクリーンショットのピクセル差分で検証しない。**アンチエイリアスのノイズが支配的で、差分から原因への逆写像が無い
- **`UNRESOLVED.md` をデザイナーへの事前質問リストにしない**
- **閾値を 0 にしない**
